# KOOMPI desktop: UX, speed and visual audit against macOS, and the plan

Audited live on 2026-10-07 on the founder's laptop: Core Ultra 7 258V, Arc 140V, 30 GB, `eDP-1` 1920x1200@60 and `HDMI-A-1` 1920x1080@60, Hyprland 0.56.2, Quickshell 0.3.1, branch `dev` at `e9521d2d7`.
Every number below was measured in that session unless it is marked as a target.
Each surface was opened through its real global shortcut or IPC, screenshotted, and closed again.
Screenshots are in `/tmp/kaudit.BPU1/` on that machine and are not committed.
Nothing was built; this document is the plan.
Shell paths are relative to `dots/.config/quickshell/koompi/`, Hyprland paths to `dots/.config/hypr/hyprland/`, everything else to the repo root.

The earlier finding that Qt apps take 6.3 s to open (`.work/AUDIT.md` B4, job J10) no longer reproduces; the remaining cost of xcb is about 2x.
Only content search moves by more than 10x, from impossible to instant; the Settings target is about 5x, the shell memory target about 3x.
The 10x is the compound of the daily flows: find, switch, change a setting, read what happened, launch.

## 2. What macOS gets right, and which of it applies

1. **One reflex per job, each instant.** Cmd+Space finds, Cmd+Tab switches, Mission Control shows everything, Control Center changes a setting, Notification Center says what happened.
   KOOMPI has the find and show reflexes; it lacks switch, and folds settings and notifications into one panel.
2. **Speed is what you perceive.** Feedback inside 100 ms (the Dock bounce), chrome animations of 200 to 300 ms, every animation interruptible, and gestures that follow the fingers and reverse mid-swipe.
3. **Quiet chrome.** The menu bar shows what you can act on; no package counts, no uptime, no developer actions; system events rarely interrupt.
4. **One icon grammar.** Every app icon sits on the same rounded-square grid with the same light; SF Symbols match the weight of the text beside them.
5. **Progressive disclosure.** The defaults are right, advanced options are one level down, and nobody is told to edit a config file.
6. **Search is the OS.** Spotlight indexes contents, apps, settings, maths and conversions in one ranked list with a Top Hit and a Quick Look preview.
7. **Accessibility switches that also save power.** Reduce Motion, Reduce Transparency, Increase Contrast.

The global menu is the Mac lesson KOOMPI has already taken, and it stays.

Popups clamp to the screen they open on.

| id | Finding | Evidence |

| S2 | Windows, settings, files, clipboard and emoji are separate modes behind sigils (`@ # ~ ; :`) listed in a footer at roughly 9 px. | screenshot |

### 3.3 Switching apps (Cmd+Tab): missing

Nothing switches apps by keyboard; `Super+Tab` is the overview (`keybinds.lua:44`) and the dock is off by default (`modules/common/Config.qml:476`).
The manual tells Mac and Windows users to press `Super+Tab` and pick from the grid (`docs/manual/01-coming-from-mac-or-windows.md:29`).

Proposal, per D3: `Alt+Tab` opens an app switcher; `Super+Tab` stays the overview.
Apps in most-recent order on uniform icon plates; `Tab` and `Shift+Tab` cycle; the window list of the selected app appears after a 300 ms dwell; `Q` closes the app; releasing `Alt` switches.
A quick tap switches to the previous app without drawing anything, as macOS does.
`Super+grave` cycles the windows of the current app.

| id | Finding | Evidence |
| --- | --- | --- |

| O2 | Every window thumbnail is a live screen copy. | `modules/koompi/overview/OverviewWindow.qml:93-97` `live: true` |

The gesture drives the overview by progress through the existing `koompi-swipe-progress` plugin, so it follows the fingers and reverses.

### 3.7 Launchpad

The grid lists developer and system utilities beside real apps: Qt V4L2 test utility, Qt V4L2 video capture utility, Qt Widgets Designer, KDE Connect SMS, PulseAudio Volume Control, Kiri Voice Popup, and three terminals.
Icon styles and sizes are mixed, and there are no folders.

Proposal: Development and System category entries go into one Utilities folder by default, as macOS does with Other; folders by dragging one icon onto another; every icon on the shared plate (section 4).

### 3.8 Cheatsheet

About a hundred rows in four columns, with raw key names (`grave`, `backslash`, `Semicolon`, `Apostrophe`, `MouseBack`, `mouse:274`, `mouse:276`, `Bracket<Direction>`) and duplicate rows (`Record region (no sound)` twice, `Terminal` twice, `Send to workspace left` three times).

Proposal: keycap glyphs for every key, one row per family (`Super+1…0`), the twenty essentials first and the rest behind its existing search.

### 3.9 Session menu

Seven icon-only tiles (lock, sleep, log out, task manager, shut down, restart, firmware); only the focused tile's name shows, under the grid, beneath two lines of keyboard instructions.

Proposal: every action labelled; shut down and restart run a short cancellable countdown instead of a second dialog; firmware setup and the task manager move to a secondary row.

### 3.10 Settings

It opens in about 1.1 s as a fresh `qs` process.
Its most prominent button is `Config file`, and a banner tells the user to edit `/home/userx/.config/koompi/config.json` by hand.
Colour schemes carry Material's internal names (Fruit Salad, Tonal Spot, Fidelity, Content), and the bar options read `Hug` and `Float`.

Proposal: a search field at the top, plain names with live swatches ("Colour from wallpaper: Vivid, Soft, Mono"), the config file under Advanced, and a window the resident shell builds on demand so it opens in about 200 ms.

### 3.11 Smaller surfaces

- **Wallpaper picker** is a file browser with a `/ home userx Pictures Wallpapers` breadcrumb and filenames such as `random_wallpaper-ws4.png` under the pictures.
  Proposal: a gallery of the KOOMPI collection, the user's photos, and time-of-day wallpapers, with no paths.
- **Media controls** with nothing playing says "Make sure your player has MPRIS support or try turning off duplicate player filtering" (`modules/koompi/mediaControls/MediaControls.qml:162`).
  Proposal: "Nothing playing" and a button for the last player.

## 4. Icons and visual identity

Today the shell uses Material Symbols Rounded for its own glyphs, the app icon theme is `breeze-plus-dark`, and the launchpad mixes flat Breeze glyphs, full-colour vendor icons and utilities with no common shape or size.
Twelve third-party themes, mostly macOS and Fluent style (WhiteSur, Mkos-Big-Sur, Fluent, Reversal), are installed in `~/.local/share/icons` and none is selected.

Per D5:

1. **One plate for every app icon** in the launchpad, search, switcher, overview and bar: a squircle that reuses Hyprland's `rounding_power = 2.5`, fixed optical sizes of 32, 48, 64 and 96, the glyph inset to 72%.
   Flat and full-colour icons then read as one family.
   Monochrome places such as the bar use symbolic icons, not desaturated colour ones.
2. **A `koompi-icons` theme**: a wide-coverage base theme plus about 40 KOOMPI-drawn icons for what people touch daily: Files, Terminal, Settings, Updates, Search, Assistant, Text editor, Screenshot, Calculator, Camera, Music, Photos, Calendar, Office, the Telegram and WhatsApp web apps, System monitor, Wallpaper, Help and Tour.
   A 1024 grid with keylines, the brand green, and the KOOMPI star as the shared motif.
3. **System glyphs matched to text.** Material Symbols is a variable font: weight set to the weight of the text beside it, fill only for the on state, optical size equal to the drawn size.
   One glyph family across the UI.
4. **On and off never by colour alone:** filled glyph, accent plate and the word "On" together.
5. **One cursor,** chosen with the mockups in item 6: Adwaita as today, or Bibata switched in all four places the cursor test reads, at 24.
6. **Before any build,** three directions rendered side by side on the launchpad, the bar and the Control Center, and the founder picks from pictures.

## 5. Speed and resource plan

- **F1 Lazy surfaces.** Bar, background, notification popups, OSD and lock stay resident; every other surface is built on first open and released after five minutes closed.
  First, measure what each surface costs by removing one loader at a time in the headless harness (an empty Quickshell measured 49 MB in an earlier session).
  Risk: a cold first open; prewarm when the pointer approaches the bar target, and fail the change if first open exceeds 100 ms.
- **F2 Motion,** per D6: open 200 ms, close 150 ms, small moves 120 ms, no overshoot on panels, workspaces 300 ms, windows 200 ms.
  Overshoot only where a finger drives the motion.
  A Reduce Motion setting turns every move into a crossfade.
- **F3 Gestures that follow the fingers** for the overview and launchpad (section 3.4).
- **F4 Qt on Wayland, staged** (decision D1, section 7).
  Now: `env.lua:30` sets `QT_QPA_PLATFORM=wayland` for the session, and `koompi-launch` sets `xcb` only for app ids on an allowlist (the id it already derives from `--id`, the desktop entry or the command), so those apps still export their menus to the bar.
  The allowlist starts from a measurement, not a guess: launch time and whether a real menubar reaches the bar, for the Qt apps KOOMPI ships.
  Apps started outside `koompi-launch` (a terminal, GIO from Telegram, D-Bus activation) run on Wayland with no bar menu, which is the accepted cost.
  Later, Phase 4: the appmenu bridge, after which the allowlist is deleted.
- **F5 Settings inside the resident shell,** about 200 ms to open.
- **F6 Live capture** only for overview tiles large enough to read.
- **F7 Reduce Transparency** in Settings, switched on automatically in power-saver; blur passes measured at 3 against 2 with `gputop` on battery.
- **F8 External monitors at their highest refresh rate,** chosen per monitor in Settings > Displays, which writes the saved rule (D7).
  The catch-all stays `preferred`: Hyprland 0.56.2's `highrr` ranks refresh before size and would run the founder's HDMI monitor at 1024x768@75, and `highres` can pick a TV's 4K@30 input mode.
- **F9 The clipboard watcher** starts `bash`, `cliphist` and a `qs` client on every copy (`execs.lua:28-29`); the shell can watch the cliphist database instead.
- **F10 Launch feedback** (section 3.11).

## 8. How each UI change is verified

Seen on screen before it is called done: both monitors (1920x1200 and 1920x1080), scale 1 and 1.25, light and dark, the Khmer locale, the horizontal and vertical bar, and with a notification, an open popup and a fullscreen window present.
Contrast is sampled from pixels, not judged by eye.
Timing claims come from a measurement on the live session after it has settled, never from the animation tokens alone.
